# 红警95 游戏循环决策清单

## 每回合标准操作流程

每一回合（每次你被要求行动时）都必须遵循以下流程：

### Step 1: 刷新状态
```
调用 get_game_state
→ 获取：金钱、电力、所有可见单位（含 actor_id）
```

### Step 2: 评估局势
根据 get_game_state 返回的信息，快速回答：
- **经济**：有钱吗？有电吗？矿车在采矿吗？
- **军事**：有军队吗？敌人位置在哪？有威胁吗？
- **建筑**：基地完整吗？有建筑被摧毁吗？

### Step 3: 选择最高优先级行动

按优先级从上到下，选第一个需要做的事：

| 优先级 | 条件 | 行动 |
|-------|------|------|
| 🔴 P0 | 游戏刚开始 | deploy_mcv 展开基地 |
| 🔴 P0 | 电力 ≤ 0 | 造电厂 |
| 🔴 P0 | 矿车全灭 | 造矿车 |
| 🔴 P0 | 正被攻击且防御不足 | 生产防御单位/调兵回防 |
| 🟡 P1 | 矿厂 < 2 且有钱 | 造矿厂扩展经济 |
| 🟡 P1 | 还没兵营 | 造兵营 |
| 🟡 P1 | 步兵 < 5 | 生产基础步兵 |
| 🟢 P2 | 地图大部分未探索 | 派兵侦查 |
| 🟢 P2 | 有军队但没看到敌人 | 移动镜头寻找敌人 |
| 🟢 P2 | 资金充足(>2000) | 攀升科技/造车间 |
| 🔵 P3 | 发现敌方基地 | 组建攻击部队 |
| 🔵 P3 | 部队数量 > 10 | 发动进攻 |

### Step 4: 执行行动
- 调用选定的工具
- **根据返回结果判断**是否成功
- 成功 → 进入下一轮决策
- 失败 → 分析原因，调整策略

### Step 5: 绝不空转
- 每回合至少调用一个工具
- 不要只输出文字不行动
- 如果不确定做什么 → `get_game_state` 再看一遍

## 工具调用纪律

### 必须遵守
1. **先查后做**：不知道 actor_id 就先 `get_game_state`
2. **真实ID**：只传工具返回的整数ID，禁止 "MCV"、"actor_1" 等字符串
3. **结果驱动**：每次工具返回后判断下一步，不要盲目重复调用
4. **一次一动作**：不要在一个回复中调用过多工具，每个工具结果都可能改变局势

### 禁止行为
- ❌ 连续重复调用同一个工具（如连续3次 move_units 到同一坐标）
- ❌ 不看返回结果就调用下一个工具
- ❌ 用字符串代替数字 actor_id
- ❌ 在游戏未结束时停止行动

## 卡死恢复策略

如果连续几轮没有有效进展（建筑没增加、军队没增加、敌人没减少）：

### 恢复清单
1. **调用 `is_game_run`**：确认游戏还在运行
2. **调用 `get_game_state`**：全面刷新状态
3. **换方向行动**：
   - 如果一直造兵没进展 → 试试侦查
   - 如果一直侦查没进展 → 试试进攻
   - 如果进攻失败 → 试试发展经济
4. **检查资金**：`query_player_info` 看是否没钱了
5. **检查队列**：`query_production_queue` 看是否卡住了

### 常见卡死原因
| 现象 | 原因 | 解决 |
|------|------|------|
| 造不出单位 | 前置建筑不够 | 用 try_buy_produce_unit 自动补齐 |
| 建筑放不下 | place_building 失败 | 再调一次，位置AI自动选 |
| 移动没反应 | 坐标不可达 | 换坐标或用 move_units_by_path |
| 攻击返回false | 目标不可见 | 先移动到视野内再攻击 |
| 钱不够 | 矿车/矿厂问题 | 检查经济，恢复采矿 |

## 胜利条件检测

当你认为可能已经胜利时：
1. 调用 `get_game_state` 确认敌方情况
2. 调用 `visible_units(type="enemy", range="all")` 看是否还有敌方单位
3. 如果敌方确实没有任何建筑和单位 → 宣布 **"胜利"**
4. 如果不确定 → 继续行动，搜索残余敌人

**重要**：只有当你确认摧毁了敌方主基地且看不到任何敌方单位时才宣布胜利。否则继续搜索和攻击。
