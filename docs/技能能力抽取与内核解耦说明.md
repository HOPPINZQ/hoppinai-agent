# 技能能力抽取与内核解耦说明

> 2026-11-02 | 把 `/skills` 命令与 `SkillLoader` 从内核移入 `capability/skill/`，并修复 SkillLoader 两个真实 bug。
> 影响范围：**全部 25 个模块**（内核 `base/ZQAgent`、`command/AgentCommandHandler`）+ 11 个启用技能的能力包。

---

## 1. 问题背景

参考实现把 `/skills` 做成内核内置命令，导致 `ZQAgent.setSessionManager(SessionManager, SkillLoader)` 与
`AgentCommandHandler(SessionManager, SkillLoader, List<AgentCommand>)` 在内核里静态持有 `SkillLoader`：

- 第 1 章 `01-baseloop`（只有 bash 工具、没有技能资源）也被迫携带 `tool/skill/SkillLoader.java` 作为"休眠依赖"
- 内核因此依赖"技能"这一具体能力，违反能力化架构的核心约束（内核不感知具体能力）
- `/skills` 与 `load_skill` 工具分属两处（内核命令 + ToolDefinition 静态字段），技能不是一个完整单元

## 2. 改动内容

### 2.1 SkillLoader 移入能力包 + 修两个 bug

`tool/skill/SkillLoader.java` → `capability/skill/SkillLoader.java`（05-skill 为权威源，复制到其余启用技能的模块）。

同时修复两个真实 bug（25 个模块的副本全部存在）：

| bug | 现象 | 修法 |
|---|---|---|
| jar 分支前缀过宽 | `entryName.startsWith("skills")` 会把 `skillsets/…/SKILL.md` 也加载进来 | 改为 `startsWith(SKILL_PATH + "/")` |
| jar 分支编码 | `new InputStreamReader(is)` 用平台默认编码，Windows（GBK）下 UTF-8 的 SKILL.md **打包后乱码**；文件分支用 `Files.readString` 默认 UTF-8 所以"开发时正常、打包后乱码" | 显式 `StandardCharsets.UTF_8`；文件分支同样显式 |

### 2.2 /skills 命令移入能力

内核 `AgentCommandHandler` 删除 `SkillLoader` 字段、`handleSkills()` 与 `case "/skills"`；
`SkillCapability.commands()` 注册 `/skills`（列出已加载技能数量与名称）。

### 2.3 内核签名简化

```java
// 之前
agent.setSessionManager(sessionManager, skillLoader);
public void setSessionManager(SessionManager sm, SkillLoader skillLoader)
public AgentCommandHandler(SessionManager sm, SkillLoader skillLoader, List<AgentCommand> extra)

// 之后
agent.setSessionManager(sessionManager);
public void setSessionManager(SessionManager sm)
public AgentCommandHandler(SessionManager sm, List<AgentCommand> extra)
```

内核（`client`/`session`/`base`/`command`）不再 import 任何技能类型。

### 2.4 模块侧调整

| 模块组 | 处理 |
|---|---|
| 技能启用（05/06/07/08/09/10/16/17/18/21/24） | 复制 `capability/skill/`；删除本地 `tool/skill`、`SkillsDefinition` 静态字段、`Tools.skillLoad`；入口注册 `SkillCapability` 并追加 `promptFragments()` |
| 仅有静态 loader、无技能工具（14/15/19/20） | 删除 `tool/skill`、静态 `skillLoader` 与其初始化、import |
| 既无技能也无 loader（01/02/03/04/11/12/13/22/23/25） | 删除 `tool/skill`（01 的"休眠依赖"随之消失） |

所有 49 处 `setSessionManager(sm, loader)` 调用改为单参。22/25 覆写的
`createCommandHandler(SessionManager, SkillLoader)` 同步改为新签名。

### 2.5 测试更新

`Agent06PromptTest` 适配：`generateSystemPrompt` 变为单参（技能清单由能力片段贡献），
新增"基础提示不含技能清单"断言；技能相关断言改为校验 `SkillCapability.promptFragments()`。

## 5. 已知遗留

1. **技能清单重复**：07/08/10/16 的基础提示仍通过 `generateSystemPrompt(ROOT, skill.getDescriptions())`
   内联清单，同时又追加 `skill.promptFragments()`（其中也含清单）——提示词里技能列表出现两次。
   后续收敛为"单一来源"：基础提示不再内联，统一由能力片段贡献。
2. **01 的 `/skills` 体验变化**：未注册技能能力时，输入 `/skills` 由"本会话未启用技能加载器"
   变为"未知命令"。如需保留友好提示，可在未注册能力时由内核保留兜底文案（不建议，内核不应感知技能）。
3. **技能资源目录**：各模块仍无 `resources/skills/`，SkillCapability 加载结果为空——
   教学演示需按 05 的说明放置技能文件。
