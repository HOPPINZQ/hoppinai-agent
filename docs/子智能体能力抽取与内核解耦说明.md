# 子智能体能力抽取与内核解耦说明

> 2026-11-02 | 承接《技能能力抽取与内核解耦说明》，把 `SubAgentSessionResult` 与子智能体运行逻辑从内核移入 `capability/subagent/`。
> 影响范围：**全部 25 个模块**（内核 `base/ZQAgent`）+ 12 个启用子智能体的能力包。

---

## 1. 问题背景

`01-baseloop` 只有 bash 一个工具、完全没有子智能体功能，但它的 `session/` 包里却有 `SubAgentSessionResult.java`。原因与技能问题同源：

- 内核 `ZQAgent` 定义了 `runTaskWithTokenUsage(String)`，返回 `session.SubAgentSessionResult`
- 内核同步要求 25 个模块的 `ZQAgent` 逐字节一致 → 所有模块（含 01）都必须携带这个类型
- 同时 `base/SubAgent.java`（子智能体实现）在 06-20 十个模块里仍是"内核侧工具"，而不是能力

结论：子智能体是**具体能力**，它的结果类型与执行逻辑都不该住在内核。

## 2. 改动内容

### 2.1 内核：去掉子智能体专属方法，补通用回调版

```java
// 删除
public SubAgentSessionResult runTaskWithTokenUsage(String prompt)

// 新增（内核只提供"跑一次任务循环 + token 回调"，不感知调用方是谁）
public String runTask(String prompt, java.util.function.Consumer<TokenUsage> usageConsumer)
```

`runTask(String)` 保留不变，`CronCapability` 等已有调用点无需改动。
内核（`base`/`command`/`client`/`session`）不再 import 任何子智能体类型。

### 2.2 SubAgentSessionResult 迁入能力包

`session/SubAgentSessionResult.java` → `capability/subagent/SubAgentSessionResult.java`（04-subagent 为权威源），
并在**全部 25 个模块删除** `session/` 下的副本。01 的会话包恢复为纯净内核类型（MessageConverter/SessionBlock/SessionData/SessionManager/SessionMessage/SessionStore/TokenUsage）。

### 2.3 子智能体实现能力化

- `SubAgent` 改为调用通用回调接口并按需聚合 token：
  ```java
  long[] tokens = new long[2];
  String text = subAgent.runTask(input.getPrompt(), usage -> {
      if (usage.getInputTokens() != null) tokens[0] += usage.getInputTokens();
      if (usage.getOutputTokens() != null) tokens[1] += usage.getOutputTokens();
  });
  SubAgentSessionResult result = SubAgentSessionResult.success(text, tokens[0], tokens[1]);
  ```
- `base/SubAgent.java` 在 06-10、16-20 十个模块**删除**，统一使用 `capability/subagent/SubAgent.java`
- `ToolDefinition.SubAgentDefinition` 静态字段与 `Tools.executeSubAgent` 一并删除
- 这十个模块的入口类注册 `SubAgentCapability` 并从基础提示追加其 `promptFragments()`

### 2.4 模块分布

| 模块 | capability/subagent |
|---|---|
| 04/05（权威源与副本） | ✔ |
| 06/07/08/09/10/16/17/18/19/20 | ✔（原 base/SubAgent 迁移而来） |
| 01/02/03/11/12/13/14/15/21/22/23/24/25 | 无（本来就无子智能体功能，只删除了死代码） |

## 4. 验证

- 全量 `mvn -o compile` 零错误（28 个 Maven 模块）
- `bin/check-kernel-sync.sh` `[OK]`（内核 24 副本逐字节一致）
- `mvn test -pl hoppinzq-module-agent-06-compact` 通过
- 全仓库 `session/SubAgentSessionResult.java`、`base/SubAgent.java` 均已清零（源码层）
- `01-baseloop` 已无任何 `SubAgent` / `sub_agent` 痕迹，会话包只剩 7 个内核类型

## 5. 遗留

1. **21/24 未注册子智能体**：这两个累积模块原本就没有 `SubAgentDefinition`，本次保持现状；
   若需要与 20 对齐，可在后续"全量能力化"时补上 `capability/subagent`。
2. **`runTask` 仍在内核**：它现在是通用"独立任务循环"（无子智能体语义），且被 `CronCapability` 复用，
   保留在内核是合理的；若后续要彻底剥离，可改为由能力组合 provider/tools 自行循环。
3. **token 聚合用 `long[]` 捕获**：Java lambda 捕获可变值的常规写法；如需更优雅可引入小型累加器类型。
