# 模块 23：沙箱

> 给狂奔的智能体戴上安全护具——命令不再直接扔给操作系统，而是先过层层安检；过不了的，把拒绝原因原样退回给模型，让循环继续而不是崩溃。

## 这个模块要解决什么问题

执行命令是智能体所有工具里最强、也最危险的一个。前面模块给它的防护一直很薄：一小份写死的危险命令黑名单，加一个超时强杀。这在演示里够用，但只要认真想让智能体真干活，就会撞上一连串问题：

- **模型会犯蠢**。它可能幻觉出一个看似合理实则致命的命令，比如想"清理空间"结果递归强删了根目录。
- **模型会被诱导**。它读到的网页、文件、别人写的注释里可能藏着指令，诱导它执行下载内容、外传数据。
- **目录会越界**。你让它在项目目录里改文件，它一个路径回退就跑到了系统目录；删错一个文件没有撤销键。
- **资源会失控**。一条自我复制的炸弹命令能在几秒内吃光全部进程名额；一条不断输出的大流量命令能把上下文和内存一起拖垮。

把"相信模型不犯蠢"当作安全策略，等于没有策略。这个模块的答案是把执行环节放进一个**受限执行环境**：任何命令都必须先通过静态安检和路径监禁，有条件时再套上系统级隔离或容器隔离，最不济也要锁住工作目录、限时强杀。

## 核心思想

**纵深防御：任何一层都会被绕过，所以层层设卡；而每一次拒绝都必须"可解释"，并以工具结果的身份回到模型手里。**

两层含义：

第一，安全不是一道墙，而是一条流水线。每层只做一件简单的事、独立生效、可以单独开关。上层的拦截基于文本判断（快、糙、便宜），下层的隔离基于操作系统机制（慢、重、可靠）。便宜的先拦，贵的后上。

第二，拒绝不是终点。被拦下的命令不会让智能体报错终止，而是返回一段带明确标记和原因的文本，作为这次工具调用的结果进入上下文。模型读到"为什么被拒"，下一轮要么换个安全做法，要么如实告诉用户。安全机制由此从"静默拦截器"变成"对话的一部分"——模型被明确教导：安全第一，不要试图绕过。

整条流水线：

```
模型给出一条命令
   │
   ▼
第一层 静态分析（黑名单模式匹配，永远开启）
   │ 命中高危模式 → 拒绝
   ▼
第二层 目录监禁（命令里的路径必须落在监禁目录内，永远开启）
   │ 有路径越界 → 拒绝
   ▼
第三层 系统级沙箱（可选，仅特定系统且装了隔离工具时生效）
   │
   ▼
第四层 容器隔离（可选，默认关闭，需要容器环境）
   │
   ▼
兜底执行（工作目录锁定在监禁目录 + 超时强杀）
```

## 工作原理

### 1. 第一层：静态分析——便宜的黑名单

这一层维护一组命名清晰的高危模式，用正则表达式匹配命令文本，命中即拒绝，并附上规则名和原因。覆盖的典型模式：

- 递归强删根目录、删除系统关键目录；
- 格式化文件系统；
- 自我复制的炸弹程序；
- 下载内容不经检查直接管道给解释器执行（远程代码执行的经典入口）；
- 向磁盘块设备裸写数据；
- 关机、重启、停机；
- 改写系统认证文件（口令库、提权配置）；
- 对根目录递归放开所有权限；
- 重定向覆盖系统关键文件。

设计上它刻意"糙"：不做命令语法解析，就是模式匹配。好处是零依赖、零开销、一眼能看懂每条规则在防什么；代价是能被变形绕过（变量拼接、编码混淆、拆成多条命令）。所以它是第一道筛子而不是最后一道——它挡住的是"一眼坏"的命令，把"看着正常"的交给后面的层。

### 2. 第二层：目录监禁——路径不许越界

这一层回答的问题更细：命令里提到的每一个路径，解析之后是不是还在允许的范围内？

工作方式是从命令文本里抽取"长得像路径的词"——以路径分隔符开头、含当前目录或上级目录记号、或带盘符的片段——逐个把它们解析成相对监禁目录的绝对路径，再做前缀比对：任何一个落在监禁目录之外，整条命令拒绝。带网络地址前缀的片段明显不是文件路径，跳过；解析失败的片段（多半是误识别的命令选项）也不拦，宁可放行交给后面的层，避免误伤正常命令。

这一层在系统里存在**两个检查点**，这是本模块最值得注意的机制设计：

```
模型发起工具调用
   │
   ├─► 检查点一：工具执行前的钩子
   │      命令类工具 → 对命令文本整体做监禁扫描
   │      带路径参数的工具 → 对路径本身做监禁校验
   │      拒绝 → 拒绝文案直接充当工具结果，工具根本不会执行
   │
   ├─► 检查点二：工具执行体内部（命令真正运行前再扫一遍）
   │      防止任何绕过钩子的调用路径
   │
   ▼
执行或拒绝
```

钩子在前面拦，好处是"拒绝即教学"——模型在执行前就知道原因，省掉一次注定失败的动作；执行体内部再拦一次，是经典的纵深防御：不假设钩子一定在位（钩子是可插拔的，能力注册顺序、是否挂载都可能变化），要害处的检查不依赖外层。

### 3. 第三层：系统级沙箱——让操作系统来管

前两层都是"看命令文本"的判断，第三层开始动真格：把命令放进一个由操作系统保证的受限环境里运行。

前提条件是运行在对应的系统上、且装了那个轻量隔离工具（探测方式很朴素：试着找一下这个程序在不在）。满足条件时，命令被包进一个几乎与外界隔绝的小天地：

- 全部隔离特性打开——独立的进程、文件、网络等命名空间，里面看不到外面的世界；
- 工作目录挂载为容器内的固定位置，并把它设为起始目录——这是里面唯一"属于它"的地方；
- 系统目录以只读方式挂进来——程序能运行，但改不了承载它的系统；
- 父进程消亡时子进程随之退出——不会留下孤儿进程。

对命令本身零修改，环境变了，能造成的破坏上限就完全不同了。

### 4. 第四层：容器隔离——整套资源配额

最后一层依赖容器环境（启动时探测容器引擎是否可用，默认关闭，需要时手动打开）。它把命令放进一个一次性的容器里，除了目录挂载，还叠加了资源配额：

- 断网——容器内没有网络，外传数据、下载执行统统失效；
- 只读根文件系统——除挂载目录外无处可写；
- 内存与处理器配额——炸弹命令最多吃掉分给它的那一点，动不了宿主机。

四层是递进的"信任收缩"：第一层假设命令文本可信度未知，第二层限定它能动哪些文件，第三层限定它能看到哪个世界，第四层限定它能用多少资源。

### 5. 兜底与失败回灌：被拒绝之后发生什么

环境再差，也至少保底一个受限执行：工作目录锁定在监禁目录、合并标准与错误输出、限时等待，超时立即强杀并明确标注"超时"；非零退出码、空输出，都如实回传。生产里最怕的不是命令失败，而是命令挂死——一条交互式命令能把整个智能体卡住，所以超时强杀是不可省略的底线。

而所有拒绝走的都是同一条回灌路径：**拒绝文案当作这次工具调用的结果，进入上下文。**文案自带醒目的拒绝标记、命中的规则名或越界的具体路径、解析后的目标位置。模型读到它，循环照常继续。系统提示词片段同时叮嘱两句：沙箱共分几层、各自防什么；被拒时如实转告用户，安全第一，不要试图绕过。

这一段是整个模块的灵魂：安全的失败方式不是"抛异常终止"，而是"把约束变成模型可理解的信息"，让模型在下一轮自己做出合规的决定。

### 6. 配置随能力走

各层的开关、超时秒数、以及一个"无限制模式"的逃生阀，都收拢在能力自己的配置里，不进全局常量。层级开关按环境自动生效（第三层只在对应系统且工具可用时启用），容器层默认关闭。逃生阀打开时跳过路径检查，专供确实需要读写任意路径的场景——默认关闭，监禁始终在位。整个能力是自包含的：删掉目录、去掉那一行注册，智能体退回"裸奔"状态，内核对沙箱一无所知。

## 一次完整运行的流转

场景一：用户说"帮我把系统临时目录清理一下"。

1. 模型构造一条带绝对路径的删除命令发起工具调用。
2. 钩子先接住：命令文本交给静态分析——路径不在根上，没命中高危模式；交给目录监禁——这个路径解析后落在监禁目录之外。
3. 拒绝文案生成："路径越界：某某路径解析后为某某绝对路径，不在监禁目录内"，它作为工具结果进入上下文，命令从未被执行。
4. 模型读到原因，向用户解释：当前监禁在项目目录，碰不了系统目录；并给出两个选项——用户手动清理，或明确放开限制后重试。没有报错，没有中断，循环自然收尾。

场景二：用户说"跑一下测试"。

1. 模型给出一条在项目目录内执行测试的命令。
2. 静态分析放行；目录监禁扫描命令里的路径片段，全部落在监禁目录内，放行。
3. 进入执行层选择：本机是对应系统且装了隔离工具，命令被包进系统级沙箱执行——独立命名空间、只读系统目录、工作目录即监禁目录。
4. 测试跑了四十秒，超过三十秒限额，进程被强杀，返回的文本带上"超时"标注。
5. 模型读到超时结果，向用户说明测试耗时超限，建议放宽时限或缩小测试范围。又一轮"失败即信息"。

场景三：用户说"删掉构建目录重新编译"。

1. 路径在监禁目录内，静态分析无命中，前两层放行。
2. 本机没装隔离工具，第三层自动跳过；容器层默认关闭；落到兜底执行——工作目录锁定、限时执行。
3. 命令正常完成，输出回灌，模型继续下一步。同样的命令，在装了隔离工具的机器上会走第三层，在开了容器的机器上会走第四层——安全等级随环境自动升降，调用方无感。

## 设计取舍

- **模式匹配，不做语法解析**。完整的命令语法解析能把"变量里藏着危险命令"这类绕过也识别出来，但复杂度陡增且依旧可绕。教学版选择简单透明：每条规则一眼看懂，同时明说它的边界——静态分析是筛子，不是保险箱。
- **文本抽词式监禁，而非系统调用拦截**。真正严密的目录限制应该在操作系统层拦每一次文件访问。从命令文本里"猜"路径是启发式的：引号包裹、变量展开、符号链接、不经路径词的输出重定向，都可能漏网。它挡住的是最常见的越界（上级目录回退、绝对路径直指系统目录），换来的是零依赖、全平台可用。漏网之鱼交给第三、四层的真隔离兜底。
- **层可选、自动降级**。环境里有什么就用什么：有隔离工具走第三层，有容器走第四层，什么都没有还有锁定目录加超时的兜底。安全等级随环境平滑伸缩，而不是"装不齐就拒绝运行"。
- **容器层默认关闭**。容器方式每次执行都要起一个容器，首次还可能拉镜像，延迟显著；对多数交互式场景过重。它定位为"高危环境的最终方案"，交给使用者自行开启。
- **拒绝即对话**。所有拒绝都走工具结果回灌，而不是抛异常终止。这让模型有机会理解约束、调整策略、向用户如实转述——安全机制融入循环，而不是悬在循环头上的铡刀。
- **两层检查点并存**。钩子层提供"执行前拦截+原因回灌"的体验，执行体内部保留同样的检查作为保险。有一点重复检查的开销，换来的是"不依赖任何外部组件在位"的安全保证。

## 在整个项目中的位置

排在模块二十二之后顺理成章：多模态让智能体多了一双眼睛，看得越多、能动的能力越强，就越需要回答"边界在哪里"。模块二十的工作区隔离解决的是"多个执行者互不干扰"，本模块解决的是"任何执行者不得越界作恶"——前者是协作秩序，后者是安全底线。

它与模块九的权限系统是互补而非重复：权限管的是"这个动作要不要先问人"，是流程层面的把关；沙箱管的是"这个动作在技术上允许到什么程度"，是执行层面的约束。一个命令可能权限上被放行、却在监禁层被拒——两道闸门各司其职。

再往后，模块二十四以宿主视角把安全连同其它机制一起重新编排进同一个循环，模块二十五在最外层加上目标判定。到了这一站，这台机器已经能看（多模态）、敢跑（全机制集成），并且终于有了刹车——而一台有刹车的车，才配得上被交给更长的路。
