# s20: Worktree Isolation（Worktree 隔离）

`s01 > ... > s18 > s19 > [ s20 ]`

> *"各干各的目录，互不干扰"* — 任务管目标，worktree 管目录，按 ID 绑定。

## 问题

s19 中，Alice 和 Bob 都在同一个目录下工作。Alice 的任务是"重构认证模块"，Bob 的任务是"重构 UI 登录页"。

Alice `write_file("config.py", ...)`。Bob 也 `write_file("config.py", ...)`。两个人改同一个文件，互相覆盖。而且无法干净地回滚 — 分不清哪些改动是谁的。

s15-s19 解决了"谁干什么"（任务系统）和"怎么通信"（消息总线），但没解决"在哪干"。

## 解决方案

![Worktree Overview](/agent/worktree-overview.svg)

Git worktree 让你在同一仓库中创建多个独立的工作目录，每个有自己的分支。Alice 在 `.worktrees/auth-refactor/` 下工作，Bob 在 `.worktrees/ui-login/` 下工作 — 互不干扰。

s20 沿用 s19 的 MessageBus、协议、自治认领机制，新增：

| 能力 | 作用 |
|------|------|
| create_worktree | 为任务创建独立目录 + 独立分支 |
| bind_task_to_worktree | 把任务和工作目录绑定（不改状态） |
| remove_worktree / keep_worktree | 完成后清理或保留 |
| validate_worktree_name | 拒绝路径穿越和非法字符 |

## 工作原理

### 1. WorktreeManager — 创建 + 任务绑定

```java
public class WorktreeManager {
    public String create(String name, String taskId) {
        validateName(name);                            // 只允许 [A-Za-z0-9._-]{1,64}
        Path path = WORKTREES_DIR.resolve(name);
        GitResult r = GitRunner.run("worktree", "add", path.toString(), "-b", "wt/" + name, "HEAD");
        if (!r.ok) return "Git error: " + r.output;
        if (taskId != null && !taskId.isEmpty()) {
            bindTaskToWorktree(taskId, name);
        }
        logEvent("create", name, taskId);
        return "Worktree '" + name + "' created at " + path;
    }

    public void bindTaskToWorktree(String taskId, String worktreeName) {
        Task task = TaskManager.load(taskId);
        task.setWorktree(worktreeName);                // 只写 worktree 字段
        TaskManager.save(task);                        // 状态保持 pending，等 teammate claim
    }
}
```

绑定规则：一个任务绑定一个 worktree。绑定**不改任务状态** — 任务仍是 `pending`，teammate 自动认领时才推进到 `in_progress`。这样 Lead 可以提前创建任务和 worktree，teammate idle 时自然认领带 worktree 的任务。

### 2. WorktreeContext — ThreadLocal 路由

每个 teammate 线程通过 ThreadLocal 持有自己的 worktree 路径。teammate 认领带 worktree 的任务时，`WorktreeContext` 自动设置路径；teammate 的 `bash`、`read_file`、`write_file` 通过 `effectiveRoot()` 路由：

```java
public class WorktreeContext {
    private static final ThreadLocal<Path> CURRENT = new ThreadLocal<>();

    public static void set(Path worktreePath) { CURRENT.set(worktreePath); }
    public static void clear()                 { CURRENT.remove(); }

    public static Path effectiveRoot() {
        Path wt = CURRENT.get();
        return wt != null ? wt : ROOT;                // 没绑定时回退到主仓库
    }
}

// 工具实现里调用：
public static String runBash(String command) {
    return shellExec(command, WorktreeContext.effectiveRoot());
}
public static String runWrite(String path, String content) {
    Path resolved = WorktreeContext.effectiveRoot().resolve(path).normalize();
    // ... 写文件
}
```

ThreadLocal 的好处是多 teammate 并发时各自隔离，文件/bash 操作天然路由到自己的 worktree，无需在每个工具调用处手动传 cwd。

### 3. 认领时自动切换

teammate 认领任务时，如果任务带 worktree，自动进入：

```java
public static String claimTask(String input) {
    String result = AutoClaimer.claim(taskId, owner);
    if (result.contains("Claimed")) {
        Task task = TaskManager.load(taskId);
        if (task.getWorktree() != null) {
            Path wtPath = WORKTREES_DIR.resolve(task.getWorktree());
            WorktreeContext.set(wtPath);
        }
    }
    return result;
}
```

### 4. GitRunner — 封装 git 命令

```java
public class GitRunner {
    public static GitResult run(String... args) {
        ProcessBuilder pb = new ProcessBuilder("git", args);
        pb.directory(ROOT.toFile());
        pb.redirectErrorStream(true);
        Process p = pb.start();
        String output = new String(p.getInputStream().readAllBytes());
        boolean ok = p.waitFor() == 0;
        return new GitResult(ok, output);
    }
}
```

`create` 和 `remove` 只在 git 命令成功后才写事件日志，保证日志反映真实状态。

### 5. 收尾：Keep 还是 Remove

任务完成后，两个选择：

```java
public String remove(String name, boolean discardChanges) {
    if (!discardChanges) {
        int[] changes = countChanges(name);     // [files, commits]
        if (changes[0] > 0 || changes[1] > 0) {
            return "有未提交改动，使用 discard_changes=true 强制删除，或 keep_worktree 保留";
        }
    }
    GitRunner.run("worktree", "remove", path.toString(), "--force");
    GitRunner.run("branch", "-D", "wt/" + name);
    logEvent("remove", name);
    return "已删除 " + name;
}

public String keep(String name) {
    logEvent("keep", name);
    return "Worktree '" + name + "' kept for review (branch: wt/" + name + ")";
}
```

Keep = 留着分支，等人工 review 后合并到主分支。Remove = 有改动时默认拒绝，需要 `discard_changes=true` 确认。**不自动 complete task** — 任务完成由 teammate 的 `complete_task` 显式触发。

### 6. 事件流 — 可审计

每次生命周期操作写入 `.worktrees/events.jsonl`：

```java
private void logEvent(String type, String name, String taskId) {
    Map<String, Object> event = Map.of(
        "type", type, "worktree", name,
        "task_id", taskId == null ? "" : taskId,
        "ts", System.currentTimeMillis());
    Files.writeString(EVENTS_LOG, JSON.write(event) + "\n",
                      StandardOpenOption.CREATE, StandardOpenOption.APPEND);
}
```

事件类型：`create` / `remove` / `keep`。教学版只记录事件用于人工排查。

## 工具数量

| 工具 | 说明 |
|------|------|
| 上一版（s19）全部工具 | 不变 |
| **create_worktree, remove_worktree, keep_worktree** | 新增 3 个 worktree 工具 |

teammate 工具数不变 — bash/read/write/edit 自动通过 `WorktreeContext.effectiveRoot()` 路由到 worktree。

## 相对 s19 的变更

| 组件 | s19 | s20 |
|------|-----|-----|
| 工作目录 | 所有 Agent 共享 ROOT | 每个任务可绑定独立 git worktree |
| Task 数据 | id/subject/status/owner/blockedBy | + worktree 字段 |
| teammate 工具 cwd | 始终 ROOT | ThreadLocal 自动路由到绑定的 worktree |
| 新增类 | — | WorktreeManager、WorktreeContext（ThreadLocal）、GitRunner |
| 新工具 | — | create_worktree, remove_worktree, keep_worktree |
| worktree 安全 | 无 | name 校验（拒绝路径穿越）+ 有改动时拒绝删除 |
| 事件日志 | 无 | `.worktrees/events.jsonl` 生命周期审计 |
