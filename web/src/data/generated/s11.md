# s11: Memory（持久化记忆）

`s01 > ... > s09 > s10 > [ s11 ] s12 ...`

> *"压缩会丢细节，要有一层不丢的"* — 文件仓库 + 索引 + 按需加载，跨压缩、跨会话。

## 问题

s06 的上下文压缩会把"用户偏好 tab 缩进"压成"用户有代码风格偏好"，细节被吃掉。新开一个会话，连摘要也没了 — agent 不知道用户上次说过什么。LLM 没有持久状态，所有信息都在上下文窗口里；上下文满了要压缩，压缩就有损。

需要一层**不参与压缩、跨会话保留**的存储。

## 解决方案

![Memory Overview](/agent/memory-overview.svg)

存储选文件系统：`.memory/` 目录下每个记忆一个 `.md`，YAML frontmatter 记录 `type/name/tags`。文件多了用索引 `MEMORY.md` 一行一条，注入到 SYSTEM prompt。

```
每轮 LLM 调用前              每轮工具循环退出后
       │                              │
       ▼                              ▼
 MemorySelector              MemoryExtractor
 读 MEMORY.md 索引            从对话中抽事实
   ↓ 调 LLM 选相关项           ↓ 调 LLM 输出 TYPE|name|tags|body
 读 .memory/*.md 正文          ↓ 写入 .memory/{type}_{name}.md
   ↓ 注入 systemPrompt          ↓ 更新 MEMORY.md 索引
                                ↓ 文件数 ≥10 触发 consolidate
```

四类记忆，各有用途：

| type | 回答什么 | 示例 |
|------|---------|------|
| user | 你是谁 | "偏好 tab 缩进" |
| feedback | 怎么做事 | "别 mock 数据库" |
| project | 正在发生什么 | "auth 重写是合规驱动" |
| reference | 东西在哪找 | "pipeline bug 在 Linear INGEST" |

## 工作原理

![Memory Subsystems](/agent/memory-subsystems.svg)

### 1. 存储格式 — Markdown + YAML frontmatter

`.memory/user_prefers_vim.md`：

```markdown
---
type: user
name: prefers_vim
tags: [editor, vim]
created: 2026-06-19T10:15:30Z
---

用户偏好使用 vim 编辑器。
```

`MEMORY.md` 是索引，一行一个链接：

```markdown
# Memory Index

- [user] prefers_vim #editor #vim — 用户偏好使用 vim 编辑器
- [feedback] no_emoji #style — 不要在回复中使用 emoji
```

写入新记忆时自动重建索引：

```java
public void writeMemoryFile(String name, String type, String tags, String body) {
    String slug = type + "_" + name.replace(" ", "_");
    Path file = MEMORY_DIR.resolve(slug + ".md");
    String content = "---\ntype: " + type + "\nname: " + name + "\ntags: " + tags + "\n---\n\n" + body;
    Files.writeString(file, content);
    rebuildIndex();
}
```

### 2. 加载 — MemorySelector 每轮选相关记忆

索引常驻 SYSTEM（可被 prompt cache 缓存），文件内容按需注入。每次用户请求开始时，`MemorySelector` 把最近对话和记忆清单（name + tags）一起发给 LLM 做一次轻量 side-query，选出相关的文件名，再读文件内容临时注入到当前 user turn。最多 5 条，控制开销：

```java
public List<Path> selectRelevant(String userInput, List<MemoryRecord> catalog) {
    if (catalog.isEmpty()) return List.of();
    String list = formatCatalog(catalog);   // "0: prefers_vim — 用户偏好使用 vim 编辑器"
    String resp = askLlm(
        "Select relevant memory indices. Return JSON array.\n\n" +
        "User input:\n" + userInput + "\n\nMemory catalog:\n" + list);
    List<Integer> indices = parseJsonArray(resp);
    return indices.stream().map(catalog::get).map(MemoryRecord::path).toList();
}
```

side-query 失败（API 错误、JSON 解析失败）时降级到关键词匹配 name + tags。

### 3. 写入 — MemoryExtractor 每轮结束后抽记忆

用户不会每次都说"记住这个"。偏好散落在正常对话中："用 tab 比空格好"、"以后都用单引号"。`extractAndSave` 在每轮工具循环退出后（说明对话告一段落）触发：

```java
// ZQAgent 主循环退出后
if (stopReason != TOOL_USE) {
    memoryExtractor.extractAndSave(history);
    memoryStore.consolidateIfNeeded();
}
```

提取前先检查已有记忆避免重复，prompt 要求 LLM 返回 `{type, name, tags, body}` 的 JSON 数组，只有确实有新信息时才写文件。

### 4. 整理 — 文件数 ≥10 触发 consolidate

记忆文件会积累。`consolidateIfNeeded()` 在文件数达到阈值（默认 10）时让 LLM 去重、合并矛盾、淘汰过时记忆：

```java
private static final int CONSOLIDATE_THRESHOLD = 10;

public void consolidateIfNeeded() {
    List<Path> files = listMemoryFiles();
    if (files.size() < CONSOLIDATE_THRESHOLD) return;
    // 把所有记忆发给 LLM，拿回去重后的列表
    List<MemoryRecord> merged = askLlmToMerge(files);
    rewriteMemoryDir(merged);
    rebuildIndex();
}
```

Claude Code 把这个过程叫 Dream，实际有四层门控（时间间隔、扫描节流、会话数、文件锁）；教学版简化为文件数阈值。

### 5. Memory 适合保存什么

跨会话仍然有用的信息：用户偏好、反复出现的反馈、项目背景、常用入口和排查线索。它关注"以后还会用到什么"，通过索引 + 按需加载把这些信息带回当前对话。session memory（s06）关注同一会话内的连续性，两者配合使用。

## 工具数量

| 工具 | 说明 |
|------|------|
| bash, read_file, write_file, edit_file, list_files, content_search | 与 s10 相同 |

记忆系统不是工具，是注入和提取的两侧管线。

## 相对 s10 的变更

| 组件 | s10 | s11 |
|------|-----|-----|
| 记忆能力 | 无 | 存储 + 加载 + 提取 + 整理 |
| 新增类 | — | MemoryRecord、MemoryStore、MemorySelector、MemoryExtractor |
| 存储 | — | `.memory/MEMORY.md` 索引 + `.memory/*.md` 文件 |
| ZQAgent | 硬编码 system | 每轮允许传不同 `effectiveSystem`，注入相关记忆 |
| 循环 | — | 入口注入 + 退出提取 + 定期整理 |
