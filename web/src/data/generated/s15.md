# s15: Dynamic System Prompt（动态系统提示）

`s01 > ... > s13 > s14 > [ s15 ] > s16 > s17 ...`

> *"prompt 是组装出来的，不是写死的"* — 分段 + 按需拼接 + context-hash 缓存。

## 问题

s01 到 s14 的 system prompt 都是一行硬编码：

```java
String SYSTEM = "You are a coding agent at " + WORKDIR + ". Use tools to solve tasks.";
```

s01 够用，只有 bash、read、write 三个工具。但到 s14，Agent 已经有 todo、子智能体、技能、压缩、任务、后台、权限、钩子、记忆、MCP、ReAct。prompt 该提的能力越来越多。三个问题：

1. **换项目要重写整个 prompt**，不知道哪些该改、哪些该留
2. **修改一处可能影响全局**，加一段工具描述可能跟前面的指令冲突
3. **每次请求都带全部内容**，即使当前对话用不到某些段落也浪费 token

system prompt 应该是运行时根据当前状态组装的配置：哪些工具启用、哪些上下文可见、哪些记忆相关、哪些内容必须保持稳定。

## 解决方案

![System Prompt Overview](/agent/system-prompt-overview.svg)

s15 聚焦 prompt 组装机制。把硬编码的 `SYSTEM` 拆成独立段落（section），运行时根据 `AgentContext` 按需拼接，缓存结果避免重复组装。

四个 section，两种加载策略：

| Section | 加载策略 | 内容 | 判断依据 |
|---------|---------|------|---------|
| identity | 始终 | 你是谁、怎么做事 | 始终存在 |
| tools | 始终 | 可用工具列表 | `toolNames` 非空 |
| workspace | 始终 | 工作目录、操作系统 | 始终存在 |
| memory | 按需 | 相关记忆内容 | `MEMORY.md` 是否存在 |

关键设计：section 是否加载取决于真实状态（工具是否注册、文件是否存在），不是消息里的关键词。

## 工作原理

### 1. AgentContext — 装配上下文

```java
@Data @Builder
public class AgentContext {
    private String workspace;            // 工作目录绝对路径
    private String osName;               // 操作系统名（小写）
    private List<String> toolNames;      // 当前已注册的工具名列表
    private boolean memoryEnabled;       // MEMORY.md 是否存在
    private String userPrompt;           // 用户当前 prompt（不进 system）

    /** 上下文 hash —— 决定是否重新装配（缓存键）。userPrompt 不算。 */
    public String cacheKey() {
        return workspace + "|" + osName + "|"
             + (toolNames == null ? "" : String.join(",", toolNames)) + "|"
             + memoryEnabled;
    }
}
```

### 2. PromptAssembler.Section — 单段定义

每个 section 是 `(name, enabled 谓词, render 函数)` 三元组：

```java
@Data @AllArgsConstructor
public static class Section {
    private final String name;
    private final Function<AgentContext, Boolean> enabled;
    private final Function<AgentContext, String> render;
}
```

构造时注册 4 个默认 section：

```java
public PromptAssembler() {
    register("identity",  ctx -> true,                                  this::renderIdentity);
    register("tools",     ctx -> ctx.getToolNames() != null && !ctx.getToolNames().isEmpty(),
                                                                            this::renderTools);
    register("workspace", ctx -> true,                                  this::renderWorkspace);
    register("memory",    AgentContext::isMemoryEnabled,                this::renderMemory);
}
```

### 3. get(ctx) — 装配 + context-hash 缓存

```java
public String get(AgentContext ctx) {
    String key = ctx.cacheKey();
    if (key.equals(lastKey)) return lastValue;          // 命中 LRU 末位
    if (cache.containsKey(key)) { lastKey = key; lastValue = cache.get(key); return lastValue; }

    StringBuilder sb = new StringBuilder();
    for (Section s : sections) {
        if (Boolean.TRUE.equals(s.getEnabled().apply(ctx))) {
            String block = s.getRender().apply(ctx);
            if (block != null && !block.isBlank()) {
                if (sb.length() > 0) sb.append("\n\n");
                sb.append(block);
            }
        }
    }
    lastKey = key; lastValue = sb.toString();
    cache.put(key, lastValue);
    return lastValue;
}
```

为什么不全加载？token 有成本（system prompt 每轮计费），信息越少 LLM 越专注。

### 4. memory section 的按需加载

`renderMemory` 检查 `MEMORY.md` 是否存在，存在才把前 1500 字符挂上：

```java
private String renderMemory(AgentContext ctx) {
    Path memoryFile = Paths.get(ctx.getWorkspace(), "MEMORY.md");
    if (!Files.isRegularFile(memoryFile)) return null;
    String text = Files.readString(memoryFile).trim();
    if (text.isEmpty()) return null;
    if (text.length() > 1500) text = text.substring(0, 1500) + "\n... (MEMORY.md 已截断)";
    return "## 持久记忆索引\n" + text;
}
```

### 5. ZQAgent 集成

每轮 while 入口前，按当前状态 build context、`assembler.get(ctx)` 拿到 effective system：

```java
AgentContext ctx = AgentContext.builder()
    .workspace(WORKDIR.toString())
    .osName(System.getProperty("os.name").toLowerCase())
    .toolNames(registeredToolNames())
    .memoryEnabled(Files.exists(WORKDIR.resolve("MEMORY.md")))
    .userPrompt(userInput)
    .build();
String effectiveSystem = promptAssembler.get(ctx);
chatMessage(messageParams, effectiveSystem);
```

## 工具数量

| 工具 | 说明 |
|------|------|
| bash, read_file, write_file, edit_file, glob, content_search | 与 s14 相同 |

prompt 装配是注入层，不影响工具集。

## 相对 s14 的变更

| 组件 | s14 | s15 |
|------|-----|-----|
| prompt | 硬编码 `SYSTEM` 字符串 | `PromptAssembler` 分段装配 |
| 缓存 | 无 | `get(ctx)` 用 `cacheKey` 命中缓存 |
| 新增类 | — | `AgentContext`、`PromptAssembler`、`PromptAssembler.Section`（PromptSection） |
| 循环 | 用固定 `SYSTEM` | 用 `assembler.get(ctx)`，每轮按状态重装 |

## 试一试

```bash
mvn -pl hoppinzq-module-agent-sysprompt -am compile
mvn -pl hoppinzq-module-agent-sysprompt exec:java -Dexec.mainClass=com.hoppinzq.agent.AgentSysPrompt
```

观察重点：

1. 输出中能看到 `[prompt] sections: identity, tools, workspace`（无 memory）
2. 让 agent 用 write_file 写一个 MEMORY.md，下一轮 system 自动追加 memory 段
3. bash 删掉 MEMORY.md，再下一轮 memory 段消失
4. 连续相同 context 的对话，缓存命中

试试这些 prompt：

1. `读 README.md` — 观察始终加载的 3 段
2. `用 write_file 创建 MEMORY.md，内容是 "# Memory\n- [test] test — test memory"` — 写入记忆索引
3. `读 README.md` — 观察 memory section 是否出现
4. `bash 删掉 MEMORY.md` — 观察下一轮 memory 段消失
