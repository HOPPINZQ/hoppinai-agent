# s09: Permission System（权限系统）

`s01 > s02 > s03 > s04 > s05 > s06 > s07 > s08 > [ s09 ] s10 > s11 > s12 ...`

> *"三道闸门：黑名单直接拒、规则匹配拒、破坏性命令问用户"* — 在工具真正执行前拦截。

## 问题

s08 的 agent 已经能 bash、写文件、跑后台任务。但模型偶尔会做出危险动作：`rm -rf /`、`sudo xxx`、`git push --force`、把文件写到工作区之外。这些动作一旦执行就是不可逆的真实后果。

**核心矛盾：**
- ❌ 没有任何拦截层，工具调用直达 shell / 文件系统
- ❌ 危险命令（`rm -rf`、`format`）一旦执行无法回滚
- ❌ 路径越界（`../escape.txt`）会写到 workspace 之外
- ❌ 破坏性但合理的命令（`rm temp.log`）一刀切禁止又太死板

## 解决方案

![Permission Overview](/agent/permission-overview.svg)

引入 **PermissionChecker** — 一条三道闸门的流水线，所有工具调用在 `invokeTool` 之前必须先过闸：

```
工具调用 (toolName, input)
   │
   ├─ 闸门 1: denyList    （rm -rf /、sudo、format C:、del /f /s /q C:\）  → 命中 → DENY
   ├─ 闸门 2: rules       （write_file 路径越出 ROOT）                     → 命中 → DENY
   └─ 闸门 3: askUser     （rm xxx、del xxx、git push --force）            → y/N → ALLOW/DENY
   │
   全部通过 → 执行工具
```

`PermissionChecker.check()` 返回 `Decision`（ALLOW / DENY / ASK），DENY 时把拒绝原因回灌给模型，让模型自己改方案；ASK 时通过 `Scanner` 弹出 `[权限确认]` 让用户决定。

## 工作原理

### 1. Decision — 决策类型 + 拒绝原因

```java
public class Decision {
    public enum Type { ALLOW, DENY, ASK }
    public final Type type;
    public final String reason;   // 拒绝/询问时给模型和用户看的解释

    public static Decision allow()              { return new Decision(Type.ALLOW, null); }
    public static Decision deny(String reason)  { return new Decision(Type.DENY, reason); }
    public static Decision ask(String reason)   { return new Decision(Type.ASK, reason); }
}
```

### 2. PermissionRules — 静态黑名单 + 路径越界

```java
public class PermissionRules {
    // 闸门 1：denyList，命中即拒
    private static final List<String> DENY = List.of(
        "rm -rf /", "rm -rf ~", "rm -rf /*",
        "sudo ", "shutdown", "reboot",
        "format C:", "format c:",
        "del /f /s /q C:\\", "mkfs"
    );

    public static Decision checkDenyList(String tool, String input) {
        if ("bash".equals(tool)) {
            for (String bad : DENY) {
                if (input.contains(bad)) return Decision.deny("命中黑名单: " + bad);
            }
        }
        return Decision.allow();
    }

    // 闸门 2：路径越界规则
    public static Decision checkPathEscape(String tool, String input) {
        if ("write_file".equals(tool) || "edit_file".equals(tool)) {
            String path = parsePath(input);
            Path resolved = ROOT.resolve(path).normalize();
            if (!resolved.startsWith(ROOT)) {
                return Decision.deny("路径越界: " + path);
            }
        }
        return Decision.allow();
    }
}
```

### 3. PermissionChecker — 三闸门流水线

```java
public class PermissionChecker {
    private final Scanner stdin;   // 用于 ASK 阶段

    public Decision checkPermission(String toolName, String input) {
        // 闸门 1
        Decision d1 = PermissionRules.checkDenyList(toolName, input);
        if (d1.type == Decision.Type.DENY) return d1;

        // 闸门 2
        Decision d2 = PermissionRules.checkPathEscape(toolName, input);
        if (d2.type == Decision.Type.DENY) return d2;

        // 闸门 3：破坏性命令交互式确认
        if (isDestructive(toolName, input)) {
            System.out.print("[权限确认] " + input + " (y/N) ");
            String line = stdin.nextLine().trim().toLowerCase();
            return "y".equals(line)
                ? Decision.allow()
                : Decision.deny("用户拒绝");
        }
        return Decision.allow();
    }

    private boolean isDestructive(String tool, String input) {
        if (!"bash".equals(tool)) return false;
        return input.matches(".*(\\brm\\b|\\bdel\\b|git push --force|chmod -R).*");
    }
}
```

### 4. ZQAgent 集成 — 工具执行前先过闸

`ZQAgent` 新增 `permissionChecker` 字段，在分发工具前调用：

```java
for (ToolUseBlock use : toolUses) {
    Decision d = permissionChecker.checkPermission(use.name(), inputJson);
    if (d.type == Decision.Type.DENY) {
        // 把拒绝原因作为 isError=true 的 ToolResult 回灌给模型
        results.add(toolResult(use.id(), "[permission denied] " + d.reason, true));
        continue;
    }
    Object output = invokeTool(use.name(), inputJson);  // 真正执行
    results.add(toolResult(use.id(), output));
}
```

模型看到拒绝原因后会自己换方案：被 `rm -rf` 拒绝 → 改用 `rm` 单文件；路径越界 → 改写到 workspace 内。

## 相对 s08 的变更

| 组件 | s08 | s09 |
|------|-----|-----|
| 拦截层 | 无 | denyList → rules → askUser 三闸门 |
| 新增类 | — | Decision、PermissionRules、PermissionChecker |
| 危险命令 | 直达 shell | 命中黑名单直接拒，路径越界直接拒 |
| 破坏性命令 | 直达 shell | 弹 y/N 交互确认 |
