# s01: The Agent Loop (智能体循环)

`[ s01 ] s02 > s03 > s04 > s05 > s06 | s07 > s08 > s09 > s10 > s11 > s12`

> *"One loop & Tool is all you need"* -- 一个工具 + 一个循环 = 一个智能体。

## 问题

语言模型能推理代码, 但碰不到真实世界 -- 不能读文件、跑测试、看报错。没有循环, 每次工具调用你都得手动把结果粘回去。你自己就是那个循环。

## 解决方案

![Agent Loop](/agent/agent-loop.svg)

```
+--------+      +-------+      +---------+
|  User  | ---> |  LLM  | ---> |  Tool   |
| prompt |      |       |      | execute |
+--------+      +---+---+      +----+----+
                    ^                |
                    |   tool_result  |
                    +----------------+
                    (loop until stop_reason != "tool_use")
```

一个退出条件控制整个流程。循环持续运行, 直到模型不再调用工具。

## 工作原理

### 1. 用户输入处理

将用户的输入添加到消息列表中。在Java中,我们使用`MessageParam`对象来表示消息:

```java
MessageParam userMessage = MessageParam.builder()
        .role(MessageParam.Role.USER)
        .content(userInput)
        .build();
messageParams.add(userMessage);
```

**代码解释**:
- `MessageParam.builder()`: 使用建造者模式创建消息参数
- `role(MessageParam.Role.USER)`: 设置消息角色为用户
- `content(userInput)`: 设置消息内容为用户输入的文本
- `messageParams`: 累积式消息列表,保存整个对话历史

### 2. 发送请求到LLM

将消息和工具定义一起发给LLM:

```java
protected Message chatMessage(List<MessageParam> messageParams){
    List<ToolUnion> anthropicTools = new ArrayList<>();
    for (ToolDefinition tool : tools) {
        anthropicTools.add(ToolUnion.ofTool(
                Tool.builder()
                        .name(tool.getName())
                        .description(tool.getDescription())
                        .inputSchema(tool.getInputSchema())
                        .build()
        ));
    }

    MessageCreateParams.Builder messageBuilder = MessageCreateParams.builder()
            .model(model)
            .messages(messageParams)
            .tools(anthropicTools);

    if (systemPrompt != null && !systemPrompt.isEmpty()) {
        messageBuilder.system(systemPrompt);
    }
    messageBuilder.maxTokens(MAX_TOKENS);
    messageBuilder.temperature(TEMPERATURE);

    return client.messages().create(messageBuilder.build());
}
```

**代码解释**:
- `ToolUnion.ofTool()`: 将工具定义转换为Anthropic API所需的格式
- `MessageCreateParams.builder()`: 构建API请求参数
- `client.messages().create()`: 发送请求到Anthropic API
- `systemPrompt`: 可选的系统提示词,用于引导LLM行为
- 返回的`Message`对象包含模型的响应内容和停止原因

### 3. 处理LLM响应 -- 打印文本 + 判断 stop_reason

每次 `create` 后做两件事: 打印 assistant 的文本块 (`printText`), 再看 `stop_reason` 决定要不要进工具循环。**官方推荐的 canonical agentic loop 以 `stop_reason == TOOL_USE` 为循环条件**, 而不是遍历 content 块自己累加 `hasToolUse` 标志 -- 因为模型可能输出空 tool_use, 或被 `max_tokens` 截断, `stop_reason` 更可靠。

```java
Message message = chatMessage(messageParams);
appendMessage(message.toParam());   // 回灌 + 持久化(若设置了 SessionManager)
printText(message);                 // 每次都打印,避免纯文本回复被静默吞掉

while (isToolUse(message)) {        // stop_reason == TOOL_USE
    MessageParam toolResultMessage = executeToolCalls(message);
    appendMessage(toolResultMessage);
    message = chatMessage(messageParams);
    appendMessage(message.toParam());
    printText(message);
}
warnIfTruncated(message);           // 命中 MAX_TOKENS 时打印警告
```

```java
private boolean isToolUse(Message message) {
    return message.stopReason()
            .map(StopReason.TOOL_USE::equals)
            .orElse(false);
}

private void printText(Message message) {
    for (ContentBlock content : message.content()) {
        if (content.isText()) {
            String text = content.text().map(TextBlock::text).orElse("");
            if (!text.isBlank()) {
                System.out.printf("AI: %s%n", text);
            }
        }
    }
}
```

**代码解释**:
- `message.stopReason()`: 模型给出的停止原因, `TOOL_USE` 表示还要继续工具循环
- `printText()`: 每轮都跑, 即使是无工具调用的纯文本回复也会被打印 (修复了老版本纯文本被吞的 bug)
- `warnIfTruncated()`: `stop_reason == MAX_TOKENS` 时打印警告, 避免工具调用被静默截断导致死循环
- `appendMessage()`: 替代裸 `messageParams.add(...)`, 若设置了 `SessionManager` 会同步把消息落盘

### 4. 执行工具并返回结果 -- executeToolCalls

`executeToolCalls` 遍历所有 tool_use 块, 匹配工具名 → `invokeTool` → 收集 `ToolResultBlockParam`, 最后封装成一条 user 角色消息返回 (内部已处理"工具未找到"和"执行抛异常"两种失败, 都标记 `isError=true` 回灌):

```java
private MessageParam executeToolCalls(Message message) {
    List<ContentBlockParam> toolResults = new ArrayList<>();
    for (ContentBlock content : message.content()) {
        if (!content.isToolUse()) continue;
        ToolUseBlock toolUse = content.asToolUse();
        // ... 匹配 tool, 调 invokeTool, 收集 toolResult / toolError ...
        toolResults.add(ContentBlockParam.ofToolResult(
                ToolResultBlockParam.builder()
                        .toolUseId(toolUse.id())
                        .content(toolError != null ? toolError.getMessage() : toolResult)
                        .isError(toolError != null)
                        .build()
        ));
    }
    return MessageParam.builder()
            .role(MessageParam.Role.USER)
            .content(MessageParam.Content.ofBlockParams(toolResults))
            .build();
}
```

`invokeTool` 第一个分支的修复值得注意: SDK 的 `JsonValue` 不能直接被 Jackson 序列化 (它是内部包装类型), 老代码 `OBJECT_MAPPER.writeValueAsString(map)` 会出错。新版本先把 `JsonValue` 落到 `JsonNode` 再组装:

```java
ObjectNode root = OBJECT_MAPPER.createObjectNode();
root.set("input", input.convert(JsonNode.class));
root.put("tool_name", tool.getName());
return tool.getFunction().apply(root.toString());
```

### 完整的智能体循环

将上述步骤组装为完整的ZQAgent类:

```java
public class ZQAgent {
    protected final AnthropicClient client;
    protected final String model;
    private final List<ToolDefinition> tools;
    protected final List<MessageParam> messageParams = new ArrayList<>();
    private String systemPrompt;
    private SessionManager sessionManager;   // 可选,设置后自动持久化 + 启动恢复

    public void run() {
        // 启动恢复: 若有历史会话, 把 .sessions/<id>.json 回灌到 messageParams
        if (sessionManager != null) {
            int n = sessionManager.historySize();
            if (n > 0) {
                sessionManager.populate(messageParams);
                System.out.printf("已恢复会话 %s,共 %d 条历史消息%n",
                        sessionManager.getSessionId(), n);
            }
        }
        System.out.println("开始对话吧");

        while (true) {
            System.out.print("你: ");
            String userInput = scanner.nextLine();
            if (userInput.isEmpty()) continue;

            MessageParam userMessage = MessageParam.builder()
                    .role(MessageParam.Role.USER)
                    .content(userInput)
                    .build();
            appendMessage(userMessage);

            Message message = chatMessage(messageParams);
            appendMessage(message.toParam());
            printText(message);

            while (isToolUse(message)) {        // stop_reason == TOOL_USE
                appendMessage(executeToolCalls(message));
                message = chatMessage(messageParams);
                appendMessage(message.toParam());
                printText(message);
            }
            warnIfTruncated(message);
        }
    }

    // appendMessage 替代裸 messageParams.add -- 设置了 sessionManager 就同步落盘
    protected void appendMessage(MessageParam param) {
        messageParams.add(param);
        if (sessionManager != null) {
            sessionManager.onMessageAppended(param);
        }
    }
}
```

**核心要点**:
- **外层循环**: 处理用户对话,持续运行直到程序退出
- **内层循环**: 以 `stop_reason == TOOL_USE` 为条件, 持续运行直到模型不再调用工具
- **消息累积**: `messageParams`保存整个对话历史,包括用户消息、AI响应和工具结果
- **退出条件**: 当 `stop_reason != TOOL_USE` 时退出内层循环 (空 tool_use / max_tokens 截断都能正确处理)
- **会话持久化**: `appendMessage` 把每条消息同步写到 `.sessions/<sessionId>.json`, 重启后可恢复

Agent01 使用**组合模式** -- 不继承ZQAgent, 而是在main方法中创建实例:

```java
public class Agent01 {
    public static void main(String[] args) {
        AnthropicClient client = AnthropicOkHttpClient.builder()
                .apiKey(API_KEY).baseUrl(BASE_URL).build();

        List<ToolDefinition> tools = new ArrayList<>();
        tools.add(BashDefinition);

        ZQAgent agent = new ZQAgent(client, MODEL, tools);
        agent.setSystemPrompt(buildSystemPrompt());
        agent.setSessionManager(bootstrapSession(args));   // 启动时恢复历史会话或开新会话
        agent.run();
    }
}
```

不到200行,这就是整个智能体。后面 20+ 个章节都在这个循环上叠加机制 -- 循环本身始终不变。

## 变更内容

| 组件 | 之前 | 之后 |
|-----|------|------|
| Agent loop | (无) | 外层 `while(true)` + 内层 `stop_reason == TOOL_USE` 驱动 |
| Tools | (无) | `bash` (单一工具) |
| Messages | (无) | `List<MessageParam>`累积式消息列表 + `appendMessage` 同步落盘 |
| Control flow | (无) | `stop_reason != TOOL_USE` 退出条件 (官方 canonical 实现) |
| Session | (无) | `.sessions/<id>.json` 自动持久化 + 启动恢复 |
| 类型安全 | 动态类型 | 静态类型,编译时检查 |
