# s16: Cron Scheduler（定时调度）

`s01 > ... > s14 > s15 > [ s16 ] > s17 > s18 ...`

> *"按时间表生产工作，调度与执行解耦"* — cron 表达式 + 双 daemon 线程 + 队列交付。

## 问题

s15 让 Agent 能动态组装 prompt、能后台执行慢操作，但所有操作仍然是你手动触发的。你说一句，Agent 动一下。"每天早上 9 点跑测试"、"每 30 分钟检查 CI 状态"、"2 分钟后提醒我"，这些周期性/延时任务不该需要人每次来推。

闹钟不需要你盯着它才会响 — 你设好 7:00，到点它自己响。

## 解决方案

![Cron Scheduler Overview](/agent/cron-scheduler-overview.svg)

s16 新增独立的 cron 调度系统：两条 daemon 线程 + 一个 `cron_queue`。调度线程每秒检查一次，时间到了把任务塞进队列；另一条 queue processor 线程在 Agent 空闲时把队列里的任务交付给 agent_loop。

| | 手动触发 (s15) | 定时触发 (s16) |
|---|---|---|
| 触发者 | 用户输入 | 调度线程 |
| 触发时机 | 随时 | cron 表达式指定 |
| 需要人参与 | 是 | 否（调度器自动入队，空闲时自动交付） |
| 持久性 | — | durable 跨重启 |

## 工作原理

### 1. CronJob — 数据结构

```java
@Data @AllArgsConstructor
public class CronJob {
    private String id;          // 8 位 hex
    private String cron;        // "0 9 * * *" — 五段式 cron 表达式
    private String prompt;      // 触发时注入给 Agent 的消息
    private boolean recurring;  // true=周期性，false=一次性
    private boolean durable;    // true=写磁盘，跨会话保留
    private String lastFired;   // "yyyy-MM-dd HH:mm" 防同分钟重复触发
}
```

五段式 cron，Unix 用了 50 年：

```
分钟  小时  日  月  星期
  *    *   *   *   *      每分钟
  0    9   *   *   *      每天早上 9:00
 */5    *   *   *   *      每 5 分钟
  0    9   *   *  1-5     工作日早上 9:00
```

支持 `*`、`*/N`、`N`、`N-M`、`N,M,...`。

### 2. CronExpression — 五段式匹配

标准 cron 语义：分钟、小时、月必须全部匹配；日（DOM）和星期（DOW）同时被约束时任一匹配即可（OR）：

```java
public boolean matches(LocalDateTime dt) {
    int dow = dt.getDayOfWeek().getValue() % 7;   // 周一=1 → cron 周日=0
    if (!matchMinute(dt) || !matchHour(dt) || !matchMonth(dt)) return false;
    boolean domUnconstrained = domField.equals("*");
    boolean dowUnconstrained = dowField.equals("*");
    if (domUnconstrained && dowUnconstrained) return true;
    if (domUnconstrained) return matchDow(dow);
    if (dowUnconstrained) return matchDom(dt);
    return matchDom(dt) || matchDow(dow);
}
```

### 3. CronScheduler — 两条 daemon 线程

调度线程跑在 daemon 里，独立于 agent_loop 是否在执行。单个 job 异常不会杀掉整个线程：

```java
// 调度线程：每秒轮询，时间到了塞进 queue
private void tickLoop() {
    while (!Thread.currentThread().isInterrupted()) {
        try { Thread.sleep(1000); } catch (InterruptedException e) { break; }
        LocalDateTime now = LocalDateTime.now();
        String marker = now.format(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm"));
        synchronized (jobs) {
            for (CronJob job : new ArrayList<>(jobs.values())) {
                try {
                    if (expressionOf(job).matches(now)
                        && !marker.equals(job.getLastFired())) {
                        queue.offer(job);
                        job.setLastFired(marker);
                        if (!job.isRecurring()) {
                            jobs.remove(job.getId());
                            if (job.isDurable()) CronStore.persist(jobs);
                        }
                    }
                } catch (Exception e) {
                    System.out.println("[cron error] " + job.getId() + ": " + e.getMessage());
                }
            }
        }
    }
}
```

queue processor 线程不检查时间，只负责在队列有任务且 Agent 空闲时拉起一轮执行：

```java
private void dispatchLoop() {
    while (!Thread.currentThread().isInterrupted()) {
        try { Thread.sleep(200); } catch (InterruptedException e) { break; }
        if (queue.isEmpty()) continue;
        if (!agentLock.tryLock()) continue;
        try {
            if (!queue.isEmpty()) runAgentTurnLocked();
        } finally { agentLock.unlock(); }
    }
}
```

生产者（调度线程）、交付者（queue processor）和消费者（agent_loop）通过 `queue`、`jobs` 锁、`agentLock` 解耦。

### 4. consumeQueue — agent_loop 消费端

agent_loop 不负责检查时间，只从 queue 拿已触发的任务，注入到 messages：

```java
public String consumeQueue() {
    StringBuilder sb = new StringBuilder();
    CronJob job;
    while ((job = queue.poll()) != null) {
        sb.append("[Scheduled] ").append(job.getPrompt()).append("\n");
    }
    return sb.toString().trim();
}

// ZQAgent 主循环入口：
String scheduled = cronScheduler.consumeQueue();
if (!scheduled.isEmpty()) {
    messages.add(new MessageParam("user", scheduled));
}
```

### 5. Durable vs Session-only

- **Durable**：`CronStore.persist(jobs)` 写入 `.scheduled_tasks.json`。Agent 重启后 `CronStore.load()` 恢复任务
- **Session-only**：只在内存里。Agent 关闭就没了

> cron 调度器必须在 Agent 进程内跑。进程关闭，调度也停。Durable 只意味着任务定义跨重启保留，下次启动时调度器才会发现"该触发了"并触发。

### 6. 三个 cron 工具

```java
public static String schedule(String input) {  // schedule_cron
    CronScheduleInput in = parse(input);
    String err = CronExpression.validate(in.cron);
    if (err != null) return err;
    CronJob job = cronScheduler.schedule(in.cron, in.prompt, in.recurring, in.durable);
    return "已注册 cron 任务 " + job.getId();
}
public static String list(String input)   { ... }  // list_crons
public static String cancel(String input) { ... }  // cancel_cron
```

## 相对 s15 的变更

| 组件 | s15 | s16 |
|------|-----|-----|
| 触发方式 | 用户手动 | 调度线程自动入队 |
| 新增类 | — | CronJob、CronExpression、CronScheduler、CronStore |
| 新存储 | — | `.scheduled_tasks.json`（durable）+ 内存（session-only） |
| 线程 | — | + 调度线程（daemon, 1s 轮询）+ queue processor 线程 |
| 队列 | — | `cron_queue`：调度写、processor 交付、agent_loop 消费 |
| 新工具 | — | schedule_cron, list_crons, cancel_cron |
