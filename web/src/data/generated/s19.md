# s19: Autonomous Agents（自主 Agent）

`s01 > ... > s17 > s18 > [ s19 ] > s20`

> *"自己看板，自己认领"* — 空闲时轮询任务板，有活就干，无需 Lead 分配。

## 问题

s18 的 teammate 能通信、能握手关机。但每个 teammate 等 Lead 分配任务 — 如果任务看板上有 10 个未认领任务，Lead 得手动 assign 10 次。这不能扩展。

teammate 应该自己看任务看板，发现没人做的任务就认领，做完再找下一个。

## 解决方案

![Autonomous Agents Overview](/agent/autonomous-agents-overview.svg)

s19 沿用 s18 的 MessageBus 和协议工具，新增：**IdlePoller**（空闲时每 5 秒轮询）、**AutoClaimer**（扫描看板上可认领的任务并自动认领）。

teammate 生命周期从两阶段变成三阶段：

| 阶段 | 行为 | 退出条件 |
|------|------|---------|
| WORK | inbox → LLM → 工具循环 | `stop_reason != tool_use` |
| IDLE | 每 5s 轮询 inbox + 任务板 | 60s 超时 |
| SHUTDOWN | 发 summary，退出 | — |

## 工作原理

### 1. IdlePoller — 空闲轮询

teammate 完成当前任务后不退出，进入 IDLE 阶段 — 每 5 秒检查一次有没有新工作：

```java
public class IdlePoller {
    private static final long POLL_INTERVAL_MS = 5000;
    private static final long IDLE_TIMEOUT_MS = 60000;

    /** 返回 "work" / "shutdown" / "timeout" */
    public String poll(String agent, List<MessageParam> messages, String name, String role) {
        long deadline = System.currentTimeMillis() + IDLE_TIMEOUT_MS;
        while (System.currentTimeMillis() < deadline) {
            Thread.sleep(POLL_INTERVAL_MS);

            // ① 检查收件箱（优先）
            List<MailboxMessage> inbox = BUS.readInbox(agent);
            if (!inbox.isEmpty()) {
                for (MailboxMessage msg : inbox) {
                    if ("shutdown_request".equals(msg.getType())) {
                        // 回复 shutdown_response
                        return "shutdown";
                    }
                }
                // 普通消息注入上下文，回到 WORK
                injectInbox(messages, inbox);
                return "work";
            }

            // ② 扫描任务看板
            List<Task> unclaimed = AutoClaimer.scanUnclaimed();
            if (!unclaimed.isEmpty()) {
                Task task = unclaimed.get(0);
                String result = AutoClaimer.claim(task.getId(), agent);
                if (result.contains("Claimed")) {
                    messages.add(new MessageParam("user",
                        "[Auto-claimed] " + task.getSubject()));
                    return "work";
                }
            }
        }
        return "timeout";
    }
}
```

inbox 优先（可能包含 shutdown_request 等协议消息），任务板其次。IDLE 阶段收到 shutdown_request 直接回复并退出，不等到下一轮 WORK。

### 2. AutoClaimer — 扫描 + 认领

找 pending 状态、无 owner、所有依赖已完成（`canStart`）的任务：

```java
public class AutoClaimer {
    public static List<Task> scanUnclaimed() {
        return TaskManager.allTasks().stream()
            .filter(t -> "pending".equals(t.getStatus()))
            .filter(t -> t.getOwner() == null)
            .filter(t -> TaskManager.canStart(t.getId()))
            .sorted(Comparator.comparing(Task::getId))
            .toList();
    }

    public static String claim(String taskId, String owner) {
        Task task = TaskManager.load(taskId);
        if (!"pending".equals(task.getStatus()))
            return "Task " + taskId + " is " + task.getStatus() + ", cannot claim";
        if (task.getOwner() != null)
            return "Task " + taskId + " already owned by " + task.getOwner();
        if (!TaskManager.canStart(taskId))
            return "Blocked by: " + task.getBlockedBy();
        task.setOwner(owner);
        task.setStatus("in_progress");
        TaskManager.save(task);
        return "Claimed " + task.getId() + " (" + task.getSubject() + ")";
    }
}
```

三个条件：必须 pending、没 owner、所有 blockedBy 依赖已完成。教学版按文件名排序取第一个；CC 用 `proper-lockfile` 防止多个 teammate 同时认领同一任务。

### 3. teammate 生命周期：WORK → IDLE → SHUTDOWN

外层循环让 WORK 和 IDLE 交替进行：

```java
// TeammateRunner 外层循环
while (true) {
    // WORK phase：内层最多 10 轮 LLM 调用
    for (int i = 0; i < MAX_TURNS; i++) {
        drainInbox(messages);
        Response resp = client.chat(...);
        messages.add(resp.assistant());
        if (!"tool_use".equals(resp.stopReason())) break;
        messages.addAll(executeTools(resp.toolUses()));
    }

    // IDLE phase
    String result = idlePoller.poll(name, messages, name, role);
    if ("shutdown".equals(result) || "timeout".equals(result)) break;
}

// SHUTDOWN：发 summary 给 Lead
BUS.send(name, "lead", summary, "result");
```

关键设计：
- **外层 while**：WORK 和 IDLE 交替，直到超时或收到关机请求
- **内层 for 10 轮**：WORK 阶段最多 10 轮 LLM 调用（防无限循环）
- **IDLE 超时 60 秒**：12 次轮询 × 5 秒 = 60 秒，超时后发 summary 退出
- **shutdown 两阶段都响应**：WORK 阶段通过 dispatcher 分发；IDLE 阶段 poller 直接检查并回复

### 4. 身份重注入

autoCompact（s06）之后，teammate 的 messages 列表可能被压成一段摘要。每次进入新的 WORK 阶段时检查：

```java
if (messages.size() <= 3) {
    messages.add(0, new MessageParam("user",
        "<identity>你是 '" + name + "', 角色: " + role + ". 继续你的工作.</identity>"));
}
```

消息过短说明发生了压缩，此时重新注入身份信息。

### 5. 新增的 task 工具

```java
create_task    → Lead 创建任务，写到 .tasks/task_xxx.json
list_tasks     → 列出所有任务
get_task       → 查单个任务详情
claim_task     → 显式认领（手动模式，与 AutoClaimer 自动模式互补）
complete_task  → 标记完成，触发依赖解锁
```

## 相对 s18 的变更

| 组件 | s18 | s19 |
|------|-----|-----|
| teammate 退出 | idle 等手动消息 | idle 时自动扫描任务板认领 |
| 生命周期 | 两阶段（WORK → SHUTDOWN） | 三阶段（WORK → IDLE → SHUTDOWN） |
| 新增类 | — | IdlePoller、AutoClaimer、TaskManager |
| 新工具 | — | create_task, list_tasks, get_task, claim_task, complete_task |

试试这些 prompt：

1. `创建 3 个任务：写 schema、写 API 路由、写测试；然后 spawn alice 和 bob，看他们自动认领` — 期望：alice 和 bob 各自从看板拿一个任务，做完后再找下一个
2. `创建带依赖的任务：task2 blockedBy task1，看 task2 在 task1 完成前不会被扫出` — 期望：AutoClaimer 检查 canStart，跳过被阻塞的
3. `spawn alice，60 秒不分配新任务，看 alice 因 IDLE 超时自动退出` — 期望：超时 SHUTDOWN，发 summary
4. `spawn alice 做事 → request_shutdown → 看 alice 即使在 IDLE 也立即响应` — 期望：IdlePoller 第一时间检查 inbox，收到 shutdown_request 立即回复

观察重点：teammate 在 IDLE 阶段是否每 5 秒扫一次任务板？多个 teammate 是否会重复认领？依赖任务是否正确阻塞？
