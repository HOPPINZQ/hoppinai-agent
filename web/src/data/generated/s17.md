# s17: Agent Teams（Agent 团队）

`s01 > ... > s15 > s16 > [ s17 ] > s18 > s19 ...`

> *"一个搞不定，组队来"* — 文件邮箱 + 守护线程，多 Agent 协作。

## 问题

"重构整个后端"涉及认证模块、数据库层、API 路由、测试。一个 Agent 在修 API 路由时，认证模块的细节已经不在上下文里了。上下文窗口就那么大，单个 Agent 的注意力覆盖不了所有模块。

s04 的子 Agent 是临时工，叫来干一件事就走了。但有些任务需要能通信、能协作、生命周期跨越多个任务的队友。

## 解决方案

![Agent Teams Overview](/agent/agent-teams-overview.svg)

s17 新增三样：**MessageBus**（文件邮箱）、**TeammateRunner**（teammate 守护线程主循环）、**inbox 注入**（Lead 接收队友消息并注入 history）。

| | s04 子 Agent | s17 队友 |
|---|---|---|
| 生命周期 | 一次性，用完销毁 | 多轮（守护线程，跑 N 轮直到 idle） |
| 通信 | 只回传结论 | 异步收件箱，随时通信 |
| 上下文 | 完全隔离 | 通过消息共享信息 |
| 数量 | 一个主 Agent + 偶尔子 Agent | 一个 Lead + 多个 teammate |

## 工作原理

![Team Topology](/agent/team-topology.svg)

### 1. MessageBus — 文件邮箱

每个 Agent（包括 Lead 和 teammate）有一个 `.jsonl` 邮箱。发消息 = 往对方的文件里 append 一行 JSON。读消息 = 读文件 + 删除（消费式）：

```java
public class MessageBus {
    public void send(String from, String to, String content, String type) {
        MailboxMessage msg = new MailboxMessage(from, to, content, type, System.currentTimeMillis());
        Path inbox = MAILBOX_DIR.resolve(to + ".jsonl");
        Files.writeString(inbox, JSON.write(msg) + "\n",
                          StandardOpenOption.CREATE, StandardOpenOption.APPEND);
    }

    public List<MailboxMessage> readInbox(String agent) {
        Path inbox = MAILBOX_DIR.resolve(agent + ".jsonl");
        if (!Files.exists(inbox)) return List.of();
        List<MailboxMessage> msgs = Files.readAllLines(inbox).stream()
            .map(line -> JSON.read(line, MailboxMessage.class)).toList();
        Files.delete(inbox);   // 消费式：读完删除
        return msgs;
    }
}
```

为什么用文件而不是内存队列？直观、跨线程可观察。真实 CC 也用文件收件箱（`~/.claude/teams/{team}/inboxes/`），但加了 `proper-lockfile` 防并发写冲突。

### 2. TeammateRunner — teammate 守护线程主循环

Lead 调用 `spawn_teammate` 工具启动一个 teammate。teammate 跑在自己的 daemon 线程里，有自己的 system prompt、自己的 messages、自己的简化工具集：

```java
public class TeammateRunner implements Runnable {
    private final String name, role;
    private final List<MessageParam> messages = new ArrayList<>();

    public void run() {
        messages.add(new MessageParam("user", initialPrompt));
        List<ToolDefinition> subTools = List.of(bash, read_file, write_file, send_message);
        for (int i = 0; i < MAX_TURNS; i++) {            // 教学版限 10 轮
            drainInboxIntoMessages();                    // 每轮先消费 inbox
            Response resp = client.chat(model, systemFor(name, role), messages, subTools);
            messages.add(resp.assistant());
            if (resp.stopReason() != TOOL_USE) break;
            messages.addAll(executeTools(resp.toolUses()));
        }
        BUS.send(name, "lead", summary(), "result");     // 完成后发 summary 给 Lead
    }

    private String systemFor(String name, String role) {
        return "你是 '" + name + "', 一个 " + role + ". 使用工具完成任务.";
    }
}
```

关键设计：
- **简化工具集**：bash、read_file、write_file、send_message。教学版省略了任务和 cron，聚焦通信机制
- **限 10 轮**：防止 teammate 无限循环。真实 CC 用 idle loop：跑完一轮后发 `idle_notification`，等 inbox 消息，收到后继续
- **完成后自动汇报**：`BUS.send(name, "lead", summary)` 把最终结果发到 Lead 的收件箱

### 3. TeammateSpawner — 启动入口

```java
public static String spawnTeammate(String input) {
    SpawnInput in = parse(input);
    Thread t = new Thread(new TeammateRunner(in.name, in.role, in.prompt), "teammate-" + in.name);
    t.setDaemon(true);
    t.start();
    activeTeammates.put(in.name, t);
    return "teammate " + in.name + " 已启动 (" + in.role + ")";
}
```

### 4. Lead 的 inbox 注入

Lead 在每轮主循环结束后检查收件箱。teammate 发来的消息注入到 history 里，让 LLM 能看到并做出反应：

```java
// ZQAgent 主循环每轮末：
List<MailboxMessage> inbox = BUS.readInbox("lead");
if (!inbox.isEmpty()) {
    String text = inbox.stream()
        .map(m -> "From " + m.getFrom() + ": " + truncate(m.getContent(), 200))
        .collect(joining("\n"));
    messages.add(new MessageParam("user", "[Inbox]\n" + text));
}
```

教学版在用户输入循环外注入。CC 更精细，Lead 的 `useInboxPoller` 每 1 秒检查一次，有消息就提交为新的 turn。

### 5. 三个 team 工具

```java
spawn_teammate  → TeammateSpawner.spawnTeammate(input)
send_message    → MessageBus.send(from, to, content, type)
check_inbox     → MessageBus.readInbox(currentAgent)
```

## 工具数量

| 工具 | 说明 |
|------|------|
| bash, read_file, write_file, edit_file, list_files, content_search | 与 s16 相同 |
| schedule_cron, list_crons, cancel_cron | 与 s16 相同 |
| **spawn_teammate, send_message, check_inbox** | 新增 3 个团队工具 |

teammate 自己只用 4 个简化工具（bash / read_file / write_file / send_message）。

## 相对 s16 的变更

| 组件 | s16 | s17 |
|------|-----|-----|
| Agent 数量 | 1 | 1 Lead + N teammate 线程 |
| 通信 | 无 | MessageBus + `.mailboxes/*.jsonl` |
| 新增类 | — | MessageBus、TeammateRunner、TeammateSpawner、MailboxMessage |
| 新工具 | — | spawn_teammate, send_message, check_inbox |
| teammate 工具 | — | bash, read_file, write_file, send_message（4 个） |
